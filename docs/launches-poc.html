Launches

A launch is a list of assets, each pinned to a version: this page, this article, this fragment. Changing what ships means changing a version on that list.

How it works

A launch keeps its own version of every asset on it. You edit those versions, preview them without touching what is live, and publish them together.

Proof of concept

Every launch gets its own copy of the item to edit. On publish the copy becomes a new version of the item and is thrown away. A launch can also be previewed in full, rendering each item at the version it pins.

Gaps

Five changes, in the order they would have to land.

  1. Let a draft belong to a version, not to the item

    Only one draft can exist per item today, which is why a launch adds a whole item of its own: addLayout, addArticle, addFragmentEntry. Held per version, an item could carry one draft for every launch in flight.

  2. Promote that draft on publish

    Publishing would mark the draft the launch has held all along as published, rather than copying its content back onto the item and deleting it. What was reviewed would be what ships.

  3. Give a page version something to render

    A LayoutContentVersion is a specification, so looking at an older one means restoring it into a hidden layout first. Either the version needs a renderable form, or rendering needs to read a specification directly.

  4. Make a branch a state, not a naming convention

    A launch's copy is told apart only by its external reference code, which the portal has to filter out wherever it resolves a page's draft or records a version. The model should say what a branch is.

  5. Make preview a property of the request

    The substitution is wired onto the service methods marked @Previewable. It would have to hold for any path that resolves an asset, so that nothing falls back to what visitors see.

Why not publications?

Liferay already ships a release this way. A publication is a list of changed database rows, where a launch is a list of assets. Only one speaks the author's language.

The same job, both ways

Six jobs on release day, answered at the top of the tree in asset versions or at the bottom in database rows. The accent marks the winner, and the last row is not ours.
